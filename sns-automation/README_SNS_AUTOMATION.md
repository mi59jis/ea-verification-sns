# EA検証ラボ SNS自動投稿キット

「SNS発信・SEO運用ガイド」の投稿スケジュール・テンプレをもとに、X・Instagram・
Threadsへの投稿を自動化するための最小構成です。noteの自動化と同じように、
GitHub Actionsで動かす前提で作っています。

**重要:このキットは「GitHub Actionsが自動で投稿する」仕組みです。**
私(Claude)がその場で投稿を代行するのではなく、あなたのGitHubリポジトリに
このフォルダを置いて、下記の手順でシークレット(認証情報)を登録すれば、
あとは月・火・水・木・金の該当時刻にGitHub側が自動的に実行してくれます。
セットアップ(シークレットの登録)は毎回ではなく、最初の1回だけです。

## 全体像

| プラットフォーム | 方式 | 費用 | 安全性 |
| --- | --- | --- | --- |
| X (旧Twitter) | ブラウザ自動操作(Playwright) | 完全無料 | ⚠️ 規約上グレー。凍結リスクあり(下記「Xを使う上でのお願い」必読) |
| Instagram | Graph API(公式) | 無料 | 公式のやり方なので安全 |
| Threads | Threads API(公式) | 無料 | 公式のやり方なので安全。Instagramビジネス化やFacebookページ連携は不要 |

X は公式APIが2026年から完全従量課金になったため、今回は「無料」を優先して
ブラウザ自動操作を選んでいます。InstagramとThreadsは公式APIが無料で使える
ので、そちらを使っています。

## フォルダ構成

```
sns-automation/
  config/
    schedule.yaml       # 曜日・時間・プラットフォーム・テンプレ種別
    templates.yaml       # 投稿本文のテンプレ
    posts_queue.csv      # 「次に投稿する内容」のキュー(自分で追記していく)
  scripts/
    post_scheduler.py    # メインの実行スクリプト(GitHub Actionsから呼ばれる)
    x_poster.py          # Xへの投稿(Playwright)
    ig_poster.py          # Instagramへの投稿(Graph API)
    threads_poster.py     # Threadsへの投稿(Threads API)
    login_once_x.py       # Xのログインセッションを作る(手動・1回だけ)
  .github/workflows/
    sns_auto_post.yml    # cronスケジュール本体
  requirements.txt
```

## セットアップ手順

### 0. リポジトリに配置する

`sns-automation/` フォルダごと、noteの自動化を置いているGitHubリポジトリ
(または新しいリポジトリ)にコミットしてください。画像をInstagram投稿で
使う都合上、**リポジトリはPublicにしておくのが一番簡単です**
(non-publicにしたい場合は後述の「画像の公開URLについて」参照)。

### 1. Instagram側の準備(公式・無料。ここが一番手間がかかります)

1. **Instagramをビジネス(またはクリエイター)アカウントに変更**
   スマホのInstagramアプリ → プロフィール編集 → アカウントの種類を切り替え、
   から変更できます。個人アカウントのままではAPIが使えません。
2. **Facebookページを作成し、Instagramと連携(PCブラウザでの手順)**

   スマホのInstagramアプリの「プロフィール編集→ビジネス向け公開情報→
   ページ」から連携する方法が案内されることが多いですが、環境によっては
   この項目が表示されないことがあります。その場合はPCブラウザから
   以下の手順で進めてください。

   a) **Facebookページを新規作成**(個人アカウントとは別物の「ページ」を作ります)
      1. PCブラウザで `facebook.com/pages/create` を開く
         (`business.facebook.com/pages/create` にリダイレクトされる場合も同じ流れです)
      2. ページ名(例: EA検証ラボ)とカテゴリを入力
      3. 「Pageを作成」をクリック(プロフィール写真などは後で設定でもOK、スキップ可)

   b) **作成したページとInstagramを連携**
      1. 作成したFacebookページを開き、「プロフェッショナルダッシュボード」→
         左メニュー「リンク済みのアカウント」→「Instagram」→
         「アカウントを連携」
      2. ポップアップでeakensholabのInstagram(プロアカウント化済みのもの)
         にログインし、連携を承認

      この画面が見当たらない場合は、Meta Business Suite
      (`business.facebook.com`)経由でも同じ結果になります:
      設定(歯車)→ビジネス設定→「アカウント」→「Instagramアカウント」→
      「追加」→Instagramでログイン→追加されたアカウントの行から、
      連携先のFacebookページを選択(自動で聞かれない場合は
      「ページを割り当てる」という操作が別途必要になることがあります)。

   > **注意**: この工程はFacebook/Instagramへのログインが必要なため、
   > 私(Claude)が代わりにログインして実行することはできません
   > (パスワードの入力はセキュリティ上の理由で代行できない操作です)。
   > お手数ですが、ご自身のブラウザで上記の手順を進めてください。
   > 途中で画面が想定と違う場合は、スクリーンショットを共有いただければ
   > 個別に手順をご案内します。
3. **Meta for Developersでアプリを作成**
   https://developers.facebook.com/ にアクセスし、「アプリを作成」。
   ユースケース選択画面では、おすすめ以外の「その他」フィルタから
   **「ユースケースなしでアプリを作成」**を選びます(「Facebookログイン」等の
   通常ユースケースから作ると、後からInstagramプロダクトを追加できない
   「Consumer」タイプに固定されてしまうため要注意)。ビジネスポートフォリオを
   選ぶ画面が出たら、お使いのビジネスポートフォリオを選択します。
4. **ユースケースを追加し、権限を設定**
   作成後、アプリのダッシュボード → 左メニュー「ユースケース」→
   「ユースケースを追加」→ カテゴリ「コンテンツ管理」から
   **「Instagramでメッセージとコンテンツを管理」**を選びます(Threadsも
   同時に使う場合は「Threads APIにアクセス」も一緒にチェックしてOKです。
   1つのアプリでInstagramとThreadsの両方を扱えます)。

   追加したユースケースのカスタマイズ画面で、タブを
   **「FacebookログインによるAPI設定」**に切り替え(デフォルトの
   「InstagramログインによるAPI設定」ではなく、Facebookページ連携を前提と
   したこちらを選ぶのがポイントです)、「1. 必要なアクセス許可を追加する」
   セクションの **「Add required content permissions」**ボタンを押します。
   これで `instagram_basic`、`instagram_content_publishing`、
   `pages_read_engagement`、`business_management`、`pages_show_list` の
   5つの権限が自動でアプリに登録されます。
   (アプリは「開発モード」のままでOKです。自分のアカウントのみに投稿する
   個人利用であれば、Meta側の本審査(App Review)は不要です。複数人・
   他人のアカウントに使う場合は審査が必要になります。)
5. **アクセストークンを取得**
   Graph API Explorer(https://developers.facebook.com/tools/explorer/)を開き、
   「Metaアプリ」で作成したアプリを選択 → 「ユーザーまたはページ」を
   **「ユーザートークン」**に設定 → 「アクセス許可」欄で手順4の5つの権限
   すべてにチェックが入っていることを確認 → 「Generate Access Token」を
   クリックし、Facebookログイン画面でページ・ビジネスへのアクセスを承認
   します(この時点のユーザートークンはすでに60日間有効な長期トークンです)。

   投稿に実際に使うのは「ページアクセストークン」なので、続けて以下を
   実行します。
   - クエリ欄に `me/accounts` と入力して送信 → 結果に含まれる
     `access_token`(ページアクセストークン)と `id`(ページID)を控えます。
     **注意**: ここで取得したページアクセストークンは短期(1時間程度)です。
   - `https://developers.facebook.com/tools/debug/accesstoken/?access_token=<上記のページアクセストークン>`
     を開き、ページ下部の**「アクセストークンを延長」**ボタンを押します
     (Facebookパスワードの再入力を求められることがあります)。
     表示された新しいトークンが60日間有効な長期ページアクセストークンです。
     これが `IG_ACCESS_TOKEN` になります。
6. **InstagramビジネスアカウントIDを調べる**
   Graph API Explorerのクエリ欄に
   `<手順5のページID>?fields=instagram_business_account,name` と入力して送信
   → `instagram_business_account.id` が `IG_BUSINESS_ACCOUNT_ID` です。

取得したら、GitHubリポジトリの Settings → Secrets and variables → Actions で
以下を登録してください。

| Secret名 | 値 |
| --- | --- |
| `IG_ACCESS_TOKEN` | 手順5で取得した長期(60日)ページアクセストークン |
| `IG_BUSINESS_ACCOUNT_ID` | 手順6で取得したビジネスアカウントID |
| `IMAGE_PUBLIC_BASE_URL` | 画像を公開しているURL(下記参照) |

60日ごとにトークンが失効するため、期限が近づいたら手順5の
「アクセストークンを延長」を再度行い、GitHub Secretsの値を更新して
ください。

**画像の公開URLについて**: Graph APIは画像をURLでしか受け取れません
(ローカルアップロード不可)。リポジトリをPublicにしているなら、

```
IMAGE_PUBLIC_BASE_URL = https://raw.githubusercontent.com/<あなたのユーザー名>/<リポジトリ名>/main/sns-automation
```

を設定すれば、`config/posts_queue.csv` の `image_path` 列(例:
`images/eyecatch_01_jp.png`)がそのままURLに変換されます。事前に
`sns-automation/images/` フォルダへ画像をコミットしておいてください。

### 2. Threads側の準備(公式・無料。Instagramより簡単です)

Threads APIは、InstagramのGraph APIと違って**ビジネスアカウント化もFacebook
ページ連携も不要**です。あなた自身のThreadsアカウント(個人アカウントのまま
でOK)に対して、Meta for Developersでアプリを作り、自分を「テスター」として
追加するだけで使えます。

**まず先に:アカウントを「eakensholab」に揃える**

いただいた状況(すでに別のThreadsアカウントは持っているが、eakensholabに
紐づいたものではない)を踏まえると、投稿主体を揃えるのが先です。Threadsは
基本的にInstagramアカウントに連動する仕組みなので、確実なのは次の方法です。

1. Threadsアプリを開く
2. プロフィールアイコン → 「アカウントを切り替える」→「別のアカウントでログイン」
3. eakensholabのInstagramアカウントでログインする
   → これでeakensholab名義のThreadsプロフィールが(なければ自動的に)作成されます

(2026年時点でThreadsは「Instagramと別のユーザー名」を設定できる表示名機能が
一部で案内されていますが、まだ環境によって挙動が異なるようです。上記の
「eakensholabのInstagramでログインする」方法が最も確実です。)

**Threads APIの設定手順**

新しいアプリを作る必要はありません。**Instagram側で作成した同じアプリ**
(「EA Kensho Content Poster」など)に、Threadsのユースケースも追加して
一緒に使えます。

1. アプリのダッシュボード → 「ユースケース」→「ユースケースを追加」→
   カテゴリ「コンテンツ管理」から**「Threads APIにアクセス」**を選択
   (Instagramのユースケースと同時に追加していた場合はこの手順は不要です)。
2. 追加したユースケースの「アクセス許可と機能」タブを開くと
   `threads_basic` は最初から「テスト準備完了」になっています。
   `threads_content_publish` の行にある**「追加」**ボタンを押して、
   同じく「テスト準備完了」にします。
3. **eakensholabをThreadsテスターとして招待**
   アプリの左メニュー「アプリの役割」→「役割」→「メンバーを追加」→
   役割は**「Threadsテスター」**を選択 → ユーザーネーム欄に
   `eakensholab` と入力して追加します。ステータスは最初「承認待ち」に
   なります。
4. **eakensholab側で招待を承認**
   eakensholabのアカウントで、Facebook/Instagramの
   アカウントセンター(`accountscenter.facebook.com`)→
   「アプリとウェブサイト」(「ウェブサイトのアクセス許可」)→
   「招待」タブを開くと、アプリ名(例: EA Kensho Content Poster)が
   表示されます。ここで招待を承認すると、開発者側の画面で
   「承認待ち」の表示が消えます(スマホのThreadsアプリ側に通知が来ない
   場合があるため、こちらのアカウントセンター経由での確認が確実です)。
5. **長期アクセストークンを発行**
   ユースケースの「設定」タブを下にスクロールすると
   「ユーザートークンの生成ツール」があります。承認済みの
   `eakensholab` の行にある**「アクセストークンを作成」**を押し、
   Threadsのログイン/認可ポップアップで承認すると、その場で
   長期(60日間)アクセストークンが発行されます
   (Instagramと違い、追加の延長作業は不要です)。これが
   `THREADS_ACCESS_TOKEN` です。
6. **自分のThreadsユーザーIDを調べる**
   発行したトークンを使って
   `GET https://graph.threads.net/v1.0/me?fields=id,username` を叩くと
   `id` が返ってきます。これが `THREADS_USER_ID` です。`username` が
   `eakensholab` になっていることを必ず確認してください。

取得したら、GitHubリポジトリの Settings → Secrets and variables → Actions で
以下を登録してください。

| Secret名 | 値 |
| --- | --- |
| `THREADS_ACCESS_TOKEN` | 手順4で取得したアクセストークン |
| `THREADS_USER_ID` | 手順5で取得したユーザーID |

Threads APIは1日あたりの投稿上限が非常に緩い(数万件レベル)ので、週2回程度
の投稿ペースでは制限を意識する必要はありません。1投稿の上限は500文字で、
今回のテンプレートはすべてそれ以内に収まることを確認済みです。

### 3. X側の準備(ブラウザ自動操作・無料)

X公式APIは使わず、あなた自身がログインした「セッション」を再利用する
方式です。パスワードを自動化スクリプトに持たせることはしません。

1. 自分のPC(Windows)で、このフォルダをダウンロードして
   ```powershell
   pip install playwright
   python -m playwright install chromium
   python scripts/login_once_x.py
   ```
2. 開いたブラウザで、いつも通り手動でXにログインする(2段階認証も
   自分で入力)。ログインできたらターミナルでEnterキーを押す。
3. `sns-automation/x_storage_state.json` が生成されるので、以下で
   Base64化してコピーする。
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("x_storage_state.json")) | Set-Clipboard
   ```
4. GitHub Secretsに `X_STORAGE_STATE_B64` として登録する。

### 4. 動作確認

GitHubの Actions タブ → 「SNS auto post (EA検証ラボ)」→
「Run workflow」から手動実行できます。`dry_run` を `true` にすると、
実際には投稿せず、内容をログに出すだけの確認ができます。まずは
`dry_run: true` で数回試してから、本番(`false`)に切り替えてください。

### 5. 投稿内容を増やす

新しい記事を出すたびに、`config/posts_queue.csv` に行を追加してください
(slot_idごとに1行、`posted` は `no` から開始)。投稿が終わると
自動的に `posted=yes` に書き換えられ、コミットされます。

## Xを使う上でのお願い(必ず読んでください)

- これは公式に認められた方法ではありません。**ログイン試行の自動化は
  一切していません**(セッションの再利用のみ)が、投稿の自動化自体が
  検知されてアカウントが凍結・制限されるリスクはゼロではありません。
- 最初の1〜2週間は、いつもの手動投稿と並行して少ない頻度で試し、
  問題が起きないか様子を見ることをおすすめします。
- 今回のスケジュール(週に3〜4投稿程度)は人間の利用頻度として不自然な
  量ではありませんが、**頻度を増やしすぎない**ことが一番のリスク低減策
  です。
- 本人確認・電話番号確認・CAPTCHAなどが表示された場合、スクリプトは
  それを突破しようとせず失敗して止まります。表示されたら自動投稿を
  一旦止め、`login_once_x.py` を再実行してセッションを更新してください。
- セッション(Cookie)には有効期限があります。数週間〜数ヶ月に一度、
  「セッション切れ」で失敗するようになったら手順2を再実行してください。
- 万一アカウントが制限された場合に備えて、投稿用アカウントとご自身の
  メインアカウントは分けておくと安心です。

## Instagramの制限事項

- ストーリーズの投稿は非対応(フィード投稿のみ)
- 24時間のローリングウィンドウで最大25投稿まで(今回のペースなら
  まったく問題になりません)
- 画像は必ず公開URL経由(ローカルファイルの直接アップロードは不可)

## Gumroad(海外版)について

Gumroadには「商品を作成・公開する」ための公式APIが**まだありません**
(2026年時点。開発元のGitHubでも要望として議論中の段階で、実装はされて
いません)。そのため、Gumroad商品の作成・公開そのものは自動化できず、
**あなた自身が手動でGumroadにログインして公開する**必要があります。

代わりに、SNS告知の部分だけ自動化に組み込んであります。

1. **公開のタイミング**: noteの新記事公開(月・木 20時ごろ)に合わせて、
   同じタイミングでGumroad側の商品もあなた自身が手動で公開してください。
   完全に同時刻でなくても、同じ日のうちであれば問題ありません。
2. **SNS告知への自動リンク追加**: `config/posts_queue.csv` に
   `gumroad_url` という列があります。その回の記事に対応するGumroad商品
   ページのURLをここに入力しておくと、`mon_launch` / `thu_launch`
   (新記事告知)の投稿本文の末尾に自動で以下の1行が追記されます。

   ```
   🌍 English / overseas version: https://your-name.gumroad.com/l/xxxxx
   ```

   `gumroad_url` を空欄のままにしておけば、この行は追記されません
   (国内版のみ告知する回はそのままでOKです)。
3. **GumroadのX連携(Gumroad自体の機能)について**: Gumroadの
   Settings → Social connections でXアカウントを連携しておくと、
   Gumroad側が商品を公開("launch")するたびに、承認した内容で
   自動的にXへ投稿してくれる機能があります。これはこの自動化キットとは
   別の、Gumroad自身が提供している機能です。今回すでに連携済みなので、
   商品を公開すると、このキットのSNS投稿(note告知)とは別に、
   Gumroad発の告知ポストもXに流れます(内容が重複してもよければ
   そのままで、投稿を減らしたい場合はどちらか一方の告知だけにしても
   構いません)。

まとめると、Gumroadに関して毎回あなたが行う作業は次の2つだけです。

- note記事の公開に合わせてGumroad商品を手動で公開する
- `posts_queue.csv` の該当行の `gumroad_url` に、そのGumroad商品ページの
  URLを入力する(告知に含めたい場合のみ)

## Payhip(海外版・2つ目)について

Payhipも同じ理由で、商品の作成・公開だけは自動化できません。Payhipの
公式APIは2026年時点で「Coupon(クーポン)」と「License key(ライセンス
キー)」の管理にしか対応しておらず、商品の作成・編集・公開に使える
エンドポイントはありません(Payhip公式のAPIリファレンスに明記されて
います)。Gumroadと同じ考え方で、SNS告知への自動リンクだけキットに
組み込んであります。

1. **公開のタイミング**: Gumroadと同じく、note新記事の公開(月・木
   20時ごろ)に合わせて、Payhip側の商品もあなた自身が手動で公開して
   ください。
2. **SNS告知への自動リンク追加**: `config/posts_queue.csv` に
   `payhip_url` という列を追加しました。その回の記事に対応するPayhip
   商品ページのURLを入力しておくと、`gumroad_url` と同様に、新記事告知
   の投稿本文の末尾に追記されます。両方入力されていれば2つとも、
   片方だけならその1つだけが載ります。

   ```
   🌍 English / overseas version
   Gumroad: https://your-name.gumroad.com/l/xxxxx
   Payhip: https://payhip.com/b/xxxxx
   ```

3. **PayhipのSNS自動連携について**: 2026年時点で調べた限り、Payhipには
   Gumroadの「Social connections」のような「商品公開時に自動でXへ投稿
   する」公式機能は見当たりませんでした。そのため、Payhip分の告知は
   このSNS自動化キット経由(上記の自動リンク追加)のみになります。

まとめると、Payhipに関して毎回あなたが行う作業も次の2つだけです。

- note記事の公開に合わせてPayhip商品を手動で公開する
- `posts_queue.csv` の該当行の `payhip_url` に、そのPayhip商品ページの
  URLを入力する(告知に含めたい場合のみ)

Gumroad用に作った商品ファイル(PDF)やサムネイル画像は、Payhipでも
そのまま使い回せます。

## Facebookの個人アカウントを非公開にしたい場合

Instagram Graph APIを使うにはFacebookページが必要ですが、これは
「個人アカウントを公開すること」とは別物です。個人プロフィールは
非公開に近い設定にしたまま、ページ(ビジネス用の別人格)だけを
公開・運用することができます。

ただしFacebookにはInstagramのような「非公開アカウント」のワンタッチ
切り替えはなく、複数の設定を個別にオフにする形になります。
設定&プライバシー→設定 の画面から、以下を順に確認してください
(すべてご自身のログイン状態で行う必要があるため、こちらも代行は
できません)。

| 設定項目 | 場所 | 変更内容 |
| --- | --- | --- |
| 今後の投稿の公開範囲 | 設定&プライバシー→設定→プライバシー | 「友達」または「自分のみ」に変更 |
| 友達リストの公開範囲 | 同上(「見つけやすさと連絡のしやすさ」) | 「自分のみ」に変更 |
| メールアドレス/電話番号での検索を許可するか | 同上 | 「友達」など最も狭い範囲に変更 |
| 外部の検索エンジンからのリンクを許可するか | 同上 | チェックを外して「オフにする」 |
| 過去の投稿の公開範囲を一括変更 | 設定&プライバシー→設定→投稿→「過去の投稿の公開範囲を制限」 | 実行(公開だった過去投稿がまとめて「友達」に変更されます。個別に戻すのは手間なので実行前に確認) |
| タグ付けされた投稿のレビュー | 設定&プライバシー→設定→プロフィールとタグ付け | 「タグ付けされた投稿を自分のタイムラインに表示する前に確認する」をオン |
| プロフィール写真ガード | プロフィール写真をクリック→オプション→「プロフィール写真ガードをオンにする」 | 地域によっては表示されないことがあります |

一番手っ取り早いのは、設定&プライバシー→「プライバシーチェックアップ」
というガイド付きツールを開いて、上から順に回答していく方法です。
公開範囲・友達リスト・検索されやすさ・タグ付けの主要項目がまとめて
確認できます。
